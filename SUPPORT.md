# Support

Thanks for using VELYXORA. This page explains where to get help and how to
report different kinds of issues.

## Technical & community support

For questions about setup, usage or development, use the repository's GitHub
Discussions or Issues (whichever the maintainer has enabled). Please search
existing threads first.

When asking for help, include:

- what you were trying to do;
- the exact steps you took;
- the tool or API involved;
- relevant, sanitized logs or error messages (no secrets).

## Bug reports

Open a GitHub Issue using the **Bug report** template. Include a clear
description, reproduction steps, expected vs. actual behavior, and your
environment. Redact secrets, tokens, cookies and personal data before posting.

## Security reports

**Do not** report security vulnerabilities as public GitHub Issues. Follow the
process in [SECURITY.md](SECURITY.md) instead, using the repository's private
vulnerability reporting mechanism when enabled.

## Voluntary support

If you would like to support the project, voluntary support options are listed
inside the application. The single source of truth for the configured methods is
`frontend/src/config/supportMethods.ts`.

Support is **entirely optional**. It never unlocks tools, grants credits,
bypasses limits or creates privileged accounts, and VELYXORA never processes
payments or stores financial data. Method identifiers and links are intentionally
not duplicated across documentation.

## Maintainer expectations

VELYXORA is maintained on a best-effort basis. There is no guaranteed response
time for support requests or bug reports. Security reports are prioritized as
described in [SECURITY.md](SECURITY.md).
